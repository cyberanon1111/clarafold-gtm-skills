# LinkedIn Content Research Workflow

The LinkedIn Content Research Workflow is a seven-step process that turns sales conversations, industry developments and category disagreements into a research-backed queue of LinkedIn topics, each with one defined claim, the evidence it requires and a traceable link to the company's positioning. One cycle takes roughly 2–3 hours.

## When to use

Use this skill when the user wants to plan LinkedIn or founder-led content, build a research-backed topic queue, or turn market signals and customer problems into content ideas tied to positioning.

## Ask the user for these inputs first

- Recent sales call notes
- Support and onboarding themes
- Industry developments
- Positioning and messaging framework

If an input is missing, say what is missing and what the output will lack without it. Do not fill gaps with invented data.

## Tools this workflow assumes

- Call recording tool
- Industry sources
- LinkedIn
- AI research assistant
- Content calendar

Use whatever the user has available (uploaded exports, connected tools, web search). Say which tools you actually used.

## Steps

1. **Mine the sales conversations.** Objections, questions and misunderstandings from recent calls are the highest-signal topic source available.
2. **Collect industry movement.** Regulation, funding, consolidation, technology shifts — anything changing the buyer's environment.
3. **Identify the disagreements.** Where does your point of view differ from the consensus? Agreement is not memorable.
4. **Check against positioning.** Every topic must reinforce the positioning. Interesting but off-message is still off-message.
5. **Define the claim.** Each topic reduces to one claim that can be argued, not a subject area.
6. **Note the evidence required.** What proof, example or experience makes the claim credible when written.
7. **Queue with a rationale.** Each item enters the calendar with the reason it exists, so production never starts from a blank page.

Work through the steps in order. Show the result of each step briefly before moving on, so the user can correct course.

## Output

Produce one document with a section for each of these:

- Research-backed topic queue
- One defined claim per topic
- Evidence requirement per claim
- Traceable link from topic to positioning

## Rules

- Use only evidence the user provides or that you can cite. Label assumptions as assumptions.
- Never invent metrics, company names, contacts or quotes.
- Prefer specific, checkable statements over general advice.
